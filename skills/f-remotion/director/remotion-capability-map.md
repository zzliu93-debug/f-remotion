# Remotion 能力边界地图

本文件用于导演方案完成初步发散后的技术收敛。它描述表达能力与风险，不提供固定版式。

## 选择原则

选择能完整保留创意作用的最低复杂度技术。`native` 不等于普通，`dependency` 也不自动更高级；独特性主要来自构图、时间、运动法则和与原镜头的关系。

所有动画必须由 `useCurrentFrame()`、`interpolate()`、`spring()` 或可复现的逐帧计算驱动。CSS transition、CSS keyframes、未设种子的随机数和依赖实时钟的动画不可用于最终渲染。

## Native：默认可承诺

在普通 Remotion + React 环境中，以下方向通常可以稳定逐帧实现：

- 中文排版：整词/整行的位移、缩放、旋转、透明度、字距、颜色、描边、下划线、删除线和共享基线重排。
- 响应式版式：Flex/Grid/absolute 布局、动态安全区换位、同位替换、分栏、堆叠、聚合、展开和尺寸插值。
- SVG 图形：线、路径、圆、形状、描边生长、虚实变化、简单 morph、遮罩与 `clipPath`。
- 局部材质：纯色、边框、局部渐变、阴影、纹理图、透明度和有限的 blend/filter；根画布仍保持透明。
- 数据与关系：真实数字计数、柱/条/点阵、路径、树、分支、区间、共同基线和状态机。
- 媒体合成：项目中已有的图像、视频、GIF/APNG/WebP、音频及按帧裁切、缩放、蒙版和时间修剪。
- 2.5D：分层视差、平面透视、CSS 3D 旋转、景深错觉和带层级的对象接力。
- 可控粒子：少量 DOM/SVG 粒子或 Canvas 粒子，位置由帧和固定 seed 决定。
- 声音数据驱动：已经能读取或预计算音频数据时，让波形、频谱或节拍响应；不得用实时麦克风或不可复现数据。

常见创意到技术的等义映射：

| 画面想法 | 首选实现 | 边界 |
| --- | --- | --- |
| 从边缘或物体后揭示文字 | `clipPath` / SVG mask / 分层遮挡 | 若要绕过真人身体，需要已有抠像或遮罩 |
| 旧状态变成新状态 | 同位替换 + 尺寸/位置/颜色插值 | 字形级 morph 需兼容路径或改用交接 |
| 路径建立关系 | SVG path + stroke 进度 | 路径必须表达真实关系 |
| 多层空间推进 | 分层 2D + perspective | 真实相机跟踪不属于纯 Remotion |
| 数量涌现或聚合 | seeded DOM/SVG/Canvas | 数量大时转 Canvas/Shader 并做性能验证 |
| 字体作为图形 | DOM/SVG + 文本测量 | 先确认字体、换行和中文字符覆盖 |
| 形状转场 | 共享几何、遮罩或同位接管 | 不要为了转场覆盖整段原片 |

## Dependency：能做，但先验证环境

以下能力需要检查 `package.json`、资产、浏览器支持和渲染性能，并先渲染代表帧与短片：

- Lottie：需要合法、完整的动画 JSON 与对应包；适合已有动画资产，不适合临时搜索一个无关模板。
- Three.js / React Three Fiber：适合真实几何、相机、光照和空间层级；平面卡片的轻微透视不值得引入 3D。
- Shader / Remotion effects：适合像素级扭曲、噪声、置换和大量并行粒子；先确认透明合成、色彩与目标编码器表现。
- Canvas/WebGL 高密度动画：适合大量对象；必须固定 seed，避免每帧创建无界对象。
- SVG 复杂 morph：路径需归一化且点数兼容；不兼容时改为分解、遮罩或交叉接管。
- 地图和地理动画：需要明确数据、投影、地图服务与授权；没有真实地理关系时不用。
- 大规模字体、视频或多媒体解码：需要确认字体可用、资产路径、帧率、色彩空间和内存。

`dependency` 方案进入计划前必须写明：依赖名称、当前是否存在、代表性测试片段和失败时的 `native` 回退。

## Preproduction：Remotion 只能合成已有结果

以下诉求不能只靠写一个 Remotion 组件可靠完成，除非项目已经提供相应资产或预计算数据：

- 真人/物体的精细抠像、头发级 rotoscope、深度图和逐帧遮挡关系。
- 镜头跟踪、平面跟踪、稳定的 3D 摄像机解算和复杂运动匹配。
- 内容感知移除、补帧、生成式扩图、原创插画、照片或写实 3D 模型。
- 写实流体、布料、烟火、破碎等高成本模拟。
- 未提供的品牌 Logo、产品 UI、真实数据、在线实时结果或需要授权的媒体。
- 需要手绘关键帧、角色表演或外部 DCC 软件制作的动画。

可行做法是先在外部流程得到透明视频、序列帧、mask、tracking JSON、深度图、3D/Lottie 资产或已核验数据，再由 Remotion 按时间合成。资产不存在时，导演必须提供等义的 `native` 方案，而不是伪造素材。

## 性能与渲染风险

- 大面积高半径 blur、多层阴影、复杂 SVG filter、全分辨率透明视频和大量 DOM 节点会显著拖慢渲染。
- 多个全屏滤镜或 blend mode 可能改变原片色相并产生平台差异；F Remotion 默认只在局部元素内部使用。
- 文字测量、字体加载和媒体元数据必须在渲染前稳定，不能依赖渲染过程中变化的网络响应。
- 复杂场景先检查进入中点、稳定态和退出中点，再渲染 1–2 秒低清连续片段；静帧正确不代表运动正确。
- 一个效果若在代表片段中出现掉帧、字体漂移、透明异常或跨机器不一致，立即使用计划中的回退方案。

## 导演可承诺的上限

Remotion 擅长的是：确定性的时间编排、网页图形系统、排版、数据、媒体和程序化运动。它也能承载 3D、shader、Lottie 和外部资产，但这些属于经过验证的扩展能力。导演可以大胆设计“画面如何变化”，但不能假设系统会自动理解视频内容、自动跟踪人物或凭空生成可靠素材。
