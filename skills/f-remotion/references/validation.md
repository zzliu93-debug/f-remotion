# 验收与渲染

## 代码检查

运行项目已有的 lint/typecheck；若没有脚本，至少执行 TypeScript 检查。确认没有 CSS transition/animation。

## 关键帧检查

每个场景至少检查：

- 进入前 1 帧。
- 进入中间帧。
- 主要信息稳定帧。
- 最后一个补充元素出现后的帧。
- 退出中间帧和下一场景首帧。

重点寻找：半字裁切、文字溢出、过暗、卡片遮脸、字幕冲突、连接线悬空、场景交叠。

```console
npx remotion still src/index.ts CompositionId analysis/check.png --frame=120 --scale=0.5
```

## 连续预览

静帧无法发现速度和衔接问题。至少渲染：

- 前 3–5 秒。
- 每个场景边界前后约 1 秒。
- 元素最多、阶段切换最多的片段。

```console
npx remotion render src/index.ts CompositionId analysis/preview.mp4 --frames=0-240 --scale=0.375 --codec=h264 --crf=22
```

检查每个动作是否跟随实际台词，而非仅仅“看起来顺”。

## 最终检查清单

- [ ] 内置 V4 样板中的微信支付文案没有被照搬到新视频。
- [ ] 没有把英文或大标题当成每段固定模板。
- [ ] 辅助信息均有字幕或项目上下文依据。
- [ ] 相邻语义组没有意外交叠。
- [ ] 关键词出现时间与口播一致。
- [ ] 长段落中存在合理的信息更新，而非长期静止或无意义循环。
- [ ] 人物面部、手势、产品和原字幕未被关键元素遮挡。
- [ ] 视频时长、分辨率、帧率与预期一致。
- [ ] 原音轨或新音轨存在且声道正常。
- [ ] 全片可从头到尾解码，无坏帧。

## 全片解码

系统存在 FFmpeg 时：

```console
ffmpeg -hide_banner -v info -i output.mp4 -map 0:v:0 -map 0:a:0 -f null NUL
```

Windows 项目若未配置全局 FFmpeg，可先在 `node_modules` 中定位 Remotion 或 `ffmpeg-static` 携带的可执行文件。只有当源视频确实没有音轨时，才允许省略音频映射。

## 反馈诊断

| 反馈 | 优先检查 |
| --- | --- |
| 太快 | 元素完成帧是否早于关键词、组内项目是否同时进入 |
| 太慢/疲劳 | 段落是否需要阶段切换、信息新增是否与台词同步 |
| 杂乱 | 是否存在无来源装饰、同屏层级是否超过三层 |
| 不像 F Remotion | 对照内置样板检查入场顺序、留白、密度和卡片材质 |
| 模板感 | 是否连续复用同一原型、是否强行使用大标题/英文 |
| 有 bug | 入场中间帧、文本测量、遮罩边界、场景首尾帧 |
