# 验收与渲染

验收分为“快速审片”和“正式交付”两级。首版的目标是尽快产出一条足以判断画面、排版、节奏和动效方向的完整视频，不用穷举检查证明它已经是最终母版。

## 1K 审片规格

- 第一版及用户确认前的修改版固定为 1K/30fps。
- 1K 指 1080p 级审片尺寸：横版 `1920×1080`，竖版 `1080×1920`，方形 `1080×1080`；其他比例保留原纵横比，以 1080 像素为基准边。
- `motion-plan.json` 始终以 30fps 为时间基准。正式输出改为其他 fps 时，先把计划帧换算成秒，再换算成运行帧。
- 审片文件使用 `*-draft-1k30-vN.mp4`；正式文件使用带目标规格的递增名称，不覆盖旧版。

## 快速审片：默认必做

每一版只执行下面这条最短路径：

1. 若本版修改了导演计划或时间轴，运行一次：

   ```console
   python scripts/validate_motion_plan.py analysis/motion-plan.json
   ```

2. 运行项目中最快的一项 lint/typecheck。若没有脚本，至少执行一次 TypeScript 检查；同一版不重复运行等价命令。
3. 直接完整渲染一条 1K/30fps 审片视频。默认不在此之前逐场景渲染证明帧或边界预览。
4. 用 `ffprobe` 或等价媒体探针核对输出的宽高、帧率、时长和音轨。探针只读取容器/流信息，不做全片逐帧解码。
5. 把审片版交给用户，由用户指出需要调整的位置。修改后只回归受影响的场景和相邻边界，再输出下一版 1K/30fps。

即使计划列出了 `proofFrames`，它们也只是导演与实现之间的状态锚点，不代表每一帧都必须单独渲染。

## 风险触发检查

只有出现明确风险时才增加检查，不把下面项目当成每版固定清单：

| 风险 | 最小检查 |
| --- | --- |
| 长中文、紧贴画面边缘、复杂遮罩 | 渲染 1 张最危险状态的静帧 |
| 人脸、手势、原字幕或产品附近排版 | 渲染 1 张遮挡最可能发生的静帧 |
| `dependency` / `preproduction` 或浏览器性能不确定 | 只渲染 1 个代表片段，失败立即使用计划中的 native 回退 |
| 场景边界、禁区边缘或退场残影复杂 | 只渲染 1 段覆盖该边界的短预览 |
| 透明画布疑似闪暗、闪亮或变色 | 抽查 1 个问题边界的无组件覆盖区域 |

一轮审片最多补 3 张风险静帧和 1 个短预览。没有具体风险时一项都不补。不要为首版制作所有边界预览、渲染式“有动效/无动效”A/B 对照或全片逐帧解码。

静帧和短预览命令示例：

```console
npx remotion still src/index.ts CompositionId analysis/risk-check.png --frame=120 --scale=0.5
npx remotion render src/index.ts CompositionId analysis/risk-preview.mp4 --frames=100-160 --scale=0.375 --codec=h264 --crf=22
```

## 用户反馈后的回归

- 只改文案、局部排版或单场编舞：检查该场景及前后一个边界。
- 改全片 palette、typography、compositionSystem 或 motionGrammar：重新做一次轻量导演自审和完整 1K/30fps 审片渲染。
- 改时间轴、禁区或场景范围：重新校验 `motion-plan.json`。
- 改纵横比：重算动态安全区与构图，并先在新比例下输出 1K/30fps 审片版。
- 只改最终分辨率或 fps 且纵横比不变：不重排时间轴；直接用秒制换算和等比布局进入正式交付。

## 正式交付：用户确认后执行

用户必须先明确确认画面版本，并给出目标分辨率和帧率。若用户尚未指定，只在此时询问一次。正式阶段不再增加未经确认的新动效。

1. 确认 Composition 使用用户指定的宽高和 fps；检查计划帧已经经秒数换算，布局已经按审片设计坐标缩放。
2. 仅对缩放敏感、风险触发或自审片后发生变化的场景做针对性静帧/短预览。
3. 正式渲染一次，并用媒体探针核对视频尺寸、帧率、时长、视频流和音轨。
4. 对最终文件做一次从头到尾解码，排除坏帧、尾帧缺失和音轨问题。

系统存在 FFmpeg 时：

```console
ffmpeg -hide_banner -v info -i output.mp4 -map 0:v:0 -map 0:a:0 -f null NUL
```

只有源视频确实没有音轨时，才允许省略音频映射。Windows 项目若未配置全局 FFmpeg，可在 `node_modules` 中定位 Remotion 或 `ffmpeg-static` 携带的可执行文件。

## 正式交付清单

- [ ] 用户已确认当前审片版，并指定正式分辨率与帧率。
- [ ] `motion-plan.json` 使用 30fps 时间基准且通过校验；正式版口播落点与审片版的真实时间一致。
- [ ] 实现忠于 selectedDirection、palette、typography、compositionSystem、surfaceSystem、motionGrammar 和 exitLogic。
- [ ] 没有从旧 V4 照搬配色、暗卡、文案、固定轮廓或淡入上移；现有组件没有反向决定方案。
- [ ] 相邻语义组无意外交叠，关键词、更新和退出与口播一致。
- [ ] 人物面部、手势、产品和原字幕未被关键元素遮挡。
- [ ] 已有截图、录屏、B-roll 或画中画禁区没有新增图层或退场残影。
- [ ] 未在用户没有要求时生成字幕；无来源英文、事实、数字、图标和品牌资产未被添加。
- [ ] 场景根画布透明，没有全屏暗部渐变、语义调色层或切组闪烁。
- [ ] 输出宽高、帧率、时长与用户规格一致，音轨存在且全片可解码。

## 反馈诊断

| 反馈 | 优先检查 |
| --- | --- |
| 太快 | 元素完成时间是否早于关键词、组内项目是否同时进入；按秒检查，不要只看帧号 |
| 太慢/疲劳 | 视觉组是否已经结束、局部信息更新是否与真实新增内容同步；不要只因秒数长就换景 |
| 背景闪烁 | 检查场景根节点是否仍有全屏渐变/调色层，或是否把背景与动效一起做整组透明度 |
| 杂乱 | 是否存在无来源装饰、同屏层级是否超过三层 |
| 不像 F Remotion | 检查透明合成、中文可读性、事实边界、人物安全、逐帧确定性和信息密度 |
| 模板感 | 回到导演阶段检查是否先看了旧库、三个方向是否只有换色、是否重复同一卡片轮廓和淡入上移 |
| 画蛇添足 | 在计划层与无动效方案对比；检查小标签、印章、高亮、图标是否重复表达主信息，不必额外渲染 A/B 视频 |
| 缺少创造力 | 检查 governingMetaphor、原镜头空间关系、三个发散方向、专属 palette/motionGrammar 与退场设计 |
| 匹配错误 | 回到 `semantic-matching.md`，检查叙事任务、关系、强调级别和时间锚点 |
| 图标/图表缺失 | 检查台词是否出现值得识别的实体或可靠可比较数据；成立时再解析资产与可视化关系 |
| 有 bug | 只检查问题场景的入场中间帧、文本测量、遮罩边界和首尾帧 |
