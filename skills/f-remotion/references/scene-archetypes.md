# 语义场景原型

本文件只能在 `analysis/motion-plan.json` 已经确定并通过校验后读取。它用于寻找与导演方案吻合的工程结构，不参与第一轮创意；若原型会改变计划中的画面母题、轮廓、调色或编舞，就忽略原型并新写组件。

## 选择规则

先问“这段话中的信息是什么关系”，再问“是否需要画面帮助”，最后才问“用什么形状”。场景原型服务于信息关系，不服务于填满画面；本表是起点，不是上限。

| 台词任务 | 信息关系 | 推荐原型 | 进入节奏 |
| --- | --- | --- | --- |
| 宣布重大变化、核心卖点 | 单一重点 | 中文重点标题 + 一条来源明确的补充信息 | 栏目头 → 主词 → 结论/标签 |
| 解释概念 | 名词与定义 | 概念名 + 定义面板 + 例子 | 概念 → 定义 → 示例 |
| 讲前提或门槛 | 条件依赖 | 上下节点、分支或门槛卡 | 目标 → 连接线 → 条件 |
| 描述因果或困境 | 原因与结果 | 因果链、决策路径 | 原因 → 中间状态 → 结果 |
| 讲步骤、成长或流程 | 顺序关系 | 编号步骤链、状态机 | 每说一步新增一步 |
| 对比过去与现在 | 对立/变化 | 左右对比、前后状态 | 旧状态 → 转折 → 新状态 |
| 列举权益、特点、例子 | 并列关系 | 卡片组、图标清单 | 总类 → 各项逐个出现 |
| 说明允许与禁止 | 边界关系 | 允许/禁止区、叉号清单 | 规则 → 受限项 → 例外/安抚 |
| 给出最终判断 | 问题与答案 | 问题提示 + 结论确认卡 | 问题 → 连接 → 答案 |
| 强调数值 | 数据关系 | 大数字 + 单位 + 对照 | 只在字幕有可靠数字时使用 |
| 提到国家、地区、平台或机构 | 实体、分类或层级 | 实体标识行 + 文字标签 + 可选标志轨 | 总类/地域 → 具体实体按口播补入 |
| 用数字证明趋势、差异或热度 | 数据证据 | 比较条、柱图、区间计数或增幅锁定 | 口径 → 基准 → 对照值 → 结论 |
| 低价值过渡、重复、口头语 | 无新增关系 | 留白 | 让人物与字幕承担表达 |
| 现有原型均不准确 | 新关系 | 按 `motion-library.md` 生成新场景 | 先比较克制、表现和留白方案 |

## 变通规则

- 时长本身不触发换景。只有叙事任务发生变化时才拆视觉组；仍在解释同一概念时保留主锚点，新增属性、证据或层级时只更新局部。
- 一个短促数字可只停留约 1.5–3 秒；一个定义可跨约 3–7 秒；一个多句论证或分层列举可持续 6–12 秒以上。以台词任务结束点为准，不把这些区间当固定模板。
- 连续两组若用了相同原型，至少改变信息组织方向；更优先重新判断第二组是否应换原型。
- 核心标题只用于真正的核心概念。普通过渡句、举例和结论不要放大成海报标题。
- 卡片数量由并列项数量决定，不为了版面对称虚构第三项。
- 连接线只表示真实关系；没有因果、顺序或归属关系时不要画线。
- 颜色使用本片导演计划声明的语义角色。旧蓝/绿/红/黄不是默认映射，也不要随机换色。
- 不要按关键词机械触发原型。同一个“但是”可能是对比、例外或语气停顿，必须阅读上下文。
- 已有原型会迫使添加无来源标题、标签、数字或步骤时，改为新创或留白。

## 辅助信息

可以使用：

- 来自字幕的上位概念、阶段名、状态、单位和类别。
- 用户明确提供的栏目名、产品名和品牌词。
- 对原句的短缩写，但不得改变含义。
- 用户提供、项目已有或来源与使用权明确的国旗、平台标志、产品图标和组织标识；图标旁保留文字标签，避免只靠图形猜测。

不可以使用：

- 无来源的进度、评分、百分比、编号、日期或英文口号。
- 内置 V4 样板中的微信支付专有文案，以及其他项目的品牌 Logo 和人物素材。
- 只为“科技感”存在的扫描线、假终端、网格或随机字符。
- 无法确认来源、品牌归属或含义的近似 Logo；拿不到可靠图标时退回文字标签或中性几何符号。

## 英文使用策略

优先保持目标视频的语言习惯。满足以下任一条件才使用英文：

1. 台词本身说出英文或行业缩写。
2. 产品官方名称必须使用英文。
3. 用户明确要求双语视觉。
4. 英文承担真实分类或单位信息，而非纯装饰。

否则用中文标题、中文状态词和符号完成层级。
