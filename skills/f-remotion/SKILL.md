# F Remotion

默认启用内部第二人格“画面动效导演”。不要询问参考视频；目标视频和字幕就是正常输入。V4 现在是制作质量基线，不是默认调色、固定版式或运动套餐。

当任务是继续优化 `f-remotion` Skill 本身，而不是用它制作视频时，额外读取 [HANDOFF.md](HANDOFF.md) 了解已确认决策、失败方向和最近验证状态。普通视频任务不要加载该维护文件。

## 三层工作方式

1. **语义编辑**：读完整台词和原片，划分叙事任务、留白、禁区与关键词帧。
2. **画面动效导演**：在不查看旧场景库的创意隔离状态下提出不同方向，确定本片独有的视觉世界，并写出可校验的 `motion-plan.json`。
3. **Remotion 实现**：计划通过后才选择技术和工程原语；现有库只能节省实现时间，不能决定设计。

## 默认双阶段交付

先快做可判断的审片版，再做正式交付，不在创意尚未确认时消耗高规格渲染和穷举检查时间。

- 第一版及用户确认前的所有修改版统一输出 `1K / 30fps`。这里的 1K 指 1080p 级审片尺寸：常见横版为 `1920×1080`，竖版为 `1080×1920`，方形为 `1080×1080`；其他比例保留原纵横比，并以 1080 像素作为基准边。
- 审片版使用递增文件名，例如 `video-draft-1k30-v1.mp4`。先让用户判断画面、排版、节奏和动效，再按反馈修改；不要因为用户尚未给出最终分辨率而阻塞第一版。
- 只有用户明确确认画面方案后，才询问或读取用户指定的最终分辨率与帧率，并渲染一次正式版。未确认前不得擅自输出 2K、4K、50/60fps 正式版。
- `motion-plan.json` 固定以 30fps 审片时间基准记录帧号。实现时先把计划帧换算成秒，再按当前 Composition 的 fps 换回运行帧，保证正式版改变帧率时口播同步和动画时长不变。
- 若正式版改变纵横比而不仅是分辨率，布局会发生实质变化：先在新比例下再给一版 1K/30fps 审片版，确认后再升规格。

## 固定与可导演的边界

固定的是透明合成、中文可读性、事实与素材来源、人物安全区、逐帧确定性、叙事分组、留白和克制的信息密度。

每条片必须由导演重新决定：

- 调色及其取色依据；旧 V4 蓝/绿/红/黄只是历史样例。
- 字体性格、字号比例、字距、对齐和数字/英文的处理。
- 构图轮廓、留白位置、表面材质、图形语言和与人物的空间关系。
- 全片运动动词、速度层级、惯性、停顿、出场顺序、更新和退场方式。
- 哪些句子完全不出现动效。

一个大视觉组仍对应一个完整叙事任务，不按字幕条数、句数或固定秒数分组。同一主锚点可跨多句驻留，只在新属性、证据、层级或转折出现时更新。

## 默认输入

优先接收：

- 一条目标视频。
- 与口播对应的 SRT、JSON 字幕或其他可换算时间轴。
- 用户希望强调或避免的内容（如果有）。

没有字幕但视频包含口播时，先生成时间轴或请求字幕。没有外部参考视频不是缺失条件，不得因此阻塞任务。

字幕文件默认只用于理解语义和建立帧时间轴，不等于要把字幕渲染进成片。除非用户明确要求显示字幕，否则不要创建字幕层；源片已有字幕时尤其不得重复叠加。

## 加载顺序与创意隔离

开始制作时：

1. 读取 [style-preset.md](references/style-preset.md)，只锁定质量、安全和合成边界。
2. 读取 [semantic-matching.md](references/semantic-matching.md)，完成台词语义标注与动效必要性判断。
3. 检查目标视频并生成字幕帧时间轴。
4. 读取内部 [画面动效导演](director/SKILL.md)，按其创意隔离规则完成发散；此时不得读取场景原型、动效库、通用组件和 V4 源码快照。
5. 导演方向确定后，读取 [Remotion 能力边界地图](director/remotion-capability-map.md)，输出并校验 `analysis/motion-plan.json`。
6. 计划通过后才可查看 `assets/style-board.svg`（本机可能另有 `approved-v4-style-board.jpg`）和可用的 V4 运动样片，只校准可读性、密度和完成度，不复制其配色、轮廓、文案或运动组合。
7. 实现阶段按需读取 [scene-archetypes.md](references/scene-archetypes.md)、[motion-library.md](references/motion-library.md)、[MotionScenes.tsx](assets/approved-v4-source/MotionScenes.tsx) 与 [VideoWithMotion.tsx](assets/approved-v4-source/VideoWithMotion.tsx)。它们是工程参考，不是导演输入。

## 硬性规则

1. 保留 F Remotion 的透明合成、中文可读性、事实边界和克制密度；具体颜色、字体、构图、材质与运动语言以本片导演计划为准。
2. 为每个语义组先判断动效必要性。低价值过渡句、重复信息和已经由人物动作表达清楚的句子可以留白。
3. 编码前必须生成并通过校验的 `analysis/motion-plan.json`。现有原型和素材库不得参与第一轮创意，也不得为了省事改写已经确定的导演方案。
4. 创意必须能用一句话解释其语义作用；解释不出来就删除。
5. 中文承担主要信息。不把英文当装饰，只保留原话、官方名称或必要行业缩写。
6. 不添加扫描线、常驻进度条、技术网格、假数据、随机字符或无来源微文案。
7. 一次只显示一个大视觉组。相邻 `<Sequence>` 不得视觉交叠，但可以保留有意留白，不需要首尾填满。
8. 关键词对应的文字、图形和状态必须在相应台词说到时进入；不得提前演完。关系成立后允许稳定驻留到叙事任务结束，不把“保持不动”误判为缺陷。
9. 长视觉组只有在台词新增了值得可视化的属性、证据、层级或转折时才局部更新或切换阶段；同一概念的继续解释保持主锚点，不使用无意义循环动画。
10. 保护人物、字幕和重要物体。布局根据逐段动态安全区决定，可以换侧、贴边、环绕或重排，不固定左侧卡片布局。
11. 所有运动使用 `useCurrentFrame()`、`interpolate()` 和 Remotion easing；不得使用 CSS transition/animation。
12. 不覆盖用户已确认的旧版本；使用递增输出文件名。
13. 先识别用户已经加入的截图、录屏、B-roll、画中画或其他信息画面，并把其完整起止时间标为硬禁区。禁区内不添加任何 Remotion 图层，包括场景根背景、栏目头和装饰元素，除非用户明确要求覆盖。
14. SRT/字幕是同步依据，不是默认交付图层。只有用户明确要求时才渲染字幕。
15. 国家、地区、平台、组织和产品图标只在能提升识别时使用，并从用户提供、项目已有或来源与使用权明确的资产中解析；图表和计数只使用可追溯的真实数值、单位与口径。
16. 全片使用导演计划中同一视觉世界，但不同视觉组必须在轮廓、阅读路径、密度或运动方式上形成有意变化；只换文案和颜色不算新场景。
17. 退场必须被设计。不得把“整组淡出”当作所有场景的默认结尾，也不得用随机换色制造变化。
18. 第一版及确认前的修改版统一为 1K/30fps 审片版；用户明确确认后，才按其指定分辨率和帧率渲染正式版。
19. 审片阶段不做逐场景穷举静帧、所有边界预览、渲染式有/无动效对照或全片逐帧解码。只有具体风险触发时才补一项针对性检查。
20. `motion-plan.json` 的帧号始终使用 30fps 审片时间基准；代码不得把这些帧号直接当成可变 fps 正式版的运行帧。
21. 用户反馈修改时只检查受影响的场景和边界；除非改变了全局时间轴、视觉系统或纵横比，不重复整套验证。

## 制作流程

### 1. 检查目标视频

读取时长、分辨率、帧率和音轨。抽取若干帧，确认：

- 人物、产品和字幕的位置。
- 各时间段可用的动态安全区、人物运动方向和可利用的原镜头边缘。
- 背景亮度是否要求换位、减少直排文字或使用导演计划中的局部可读性表面。
- 用户已插入的截图、录屏、B-roll、画中画和信息卡的起止时间。

把已插入画面的区间记录为 `excludedRanges`。若一个语义组跨越禁区，拆分、延后或留白，不得让 `<Sequence>`、场景根背景或退场残影进入禁区。

16:9 使用统一设计坐标；其他比例按 [style-preset.md](references/style-preset.md) 的缩放与重排规则处理。

### 2. 建立字幕帧时间轴

运行：

```console
python scripts/srt_to_timeline.py input.srt --fps 30 --format markdown
```

按话题转折、因果、步骤、列举和结论合并字幕，不按相等时长切段。此时只做语义编辑，不决定画面外形。为每组先记录：

```text
visualGroupId | 起止帧 | 对应原话 | 画面状态/禁区 | 叙事任务 | 语义关系 | 情绪变化 | 强调级别 | 视觉必要性 | enter/update/hold/exit/blank | 关键词帧 | 驻留/留白理由
```

### 3. 画面动效导演先行

读取 [director/SKILL.md](director/SKILL.md) 并切换到导演人格。它必须：

1. 通读完整台词与关键镜头，提炼本片的核心冲突、情绪曲线和画面母题。
2. 在不查看旧场景库的条件下提出至少三个主轮廓、阅读路径与运动法则都不同的方向。
3. 选择一个统一方向，定义本片专属的调色、字体层级、构图、材质、运动语法与主动留白。
4. 为每个视觉组写出稳定态、z-order、出场顺序、更新、驻留、退场、关键帧与无动效对照。
5. 读取 [remotion-capability-map.md](director/remotion-capability-map.md)，标记 `native`、`dependency` 或 `preproduction`，并为高风险方案提供等义回退。
6. 输出 `analysis/motion-plan.json`。

除非用户明确要求先确认导演方案，否则这是内部制作关卡，不额外中断任务。导演计划尚未通过时，不得开始 JSX。

运行：

```console
python scripts/validate_motion_plan.py analysis/motion-plan.json
```

校验失败时修正计划，而不是跳过。校验通过只代表结构与时间可执行；仍需用导演自审检查模板感、画面差异与审美完整性。

### 4. 实现

读取 [implementation.md](references/implementation.md)，以通过校验的 `motion-plan.json` 为实现契约。先按计划拆出业务场景，再判断哪些运动值得复用原语；不要先复制整个 `SemanticMotionPrimitives.tsx` 再寻找用途。

- 用 `<Sequence>` 标记每个 `visualGroupId`；一个组可跨越多句台词。
- 每个计划事件都有明确的绝对帧、目标元素、动作和阅读作用。
- 计划帧是 30fps 审片时间基准。先换算为秒，再用 `useVideoConfig().fps` 得到运行帧；正式输出切换 fps 时不得手工重排每个事件。
- 以计划中的审片宽高作为设计坐标，按当前 Composition 尺寸缩放；同纵横比直接等比缩放，改变纵横比则先重排并重新出 1K/30fps 审片版。
- 颜色、字体、圆角、描边、阴影、缓动和运动方向来自本片计划，不从旧组件默认值继承。
- 计划标为 `native` 的场景优先用 HTML/CSS/SVG/Canvas 实现；`dependency` 先做代表片段；缺失外部资产时执行计划中的回退。
- 原型和 `SemanticMotionPrimitives.tsx` 只可复用与导演计划完全一致的底层能力；其默认外观必须参数化或移除。
- 实现发现不可行时回到导演阶段更新计划，不得悄悄退化成旧卡片模板。

### 5. 验证并渲染

读取 [validation.md](references/validation.md)，按阶段执行：

**审片版（默认）**

1. `motion-plan.json` 只校验一次；运行项目最快的一项 lint/typecheck。
2. 默认不预渲染逐场景 `proofFrames`、多个边界片段或 A/B 视频。只有依赖、复杂遮罩、紧贴安全区、长中文溢出或高风险衔接存在时，补少量针对性检查。
3. 直接完整渲染一版 1K/30fps 审片视频，并用媒体探针核对分辨率、帧率、时长和音轨；不做全片逐帧解码。
4. 把审片版交给用户决定修改点。修改后只回归受影响场景，再输出下一版 1K/30fps。

**正式版（用户明确确认后）**

1. 读取用户指定的分辨率与帧率；若只改变同纵横比规格，不重做创意和时间轴。
2. 对缩放敏感或改动过的场景做针对性检查，正式渲染一次。
3. 核对媒体参数并做一次全片解码，确认视频与音轨完整。正式版阶段不再悄悄增加新设计。

## 学习外部参考片

当用户提供参考片并要求学习、扩充能力或更换风格时，读取 [reference-analysis.md](references/reference-analysis.md)。把观察结果拆成视觉语法、运动机制、话题内容和素材依赖四类：

- 只把可迁移的运动机制加入候选能力库。
- 不自动改变 F Remotion 的事实、安全和合成底线；可把可迁移的构图或运动机制作为导演候选，但不复制专有英文、品牌、素材、假数据或依赖原片氛围的装饰。
- 先在真实视频中验证匹配性。用户确认合适后才提升为推荐能力；不合适时记录为“本次不匹配”，不要为了证明学会了而硬加。
- 没有外部参考片时，直接由画面动效导演从目标视频与台词生成方向，不得向用户索要参考视频。
