# f-remotion 交接状态

> 更新时间：2026-09-11。此文件用于新的 Codex 对话接续维护和迭代，不属于普通视频任务的运行时风格规范。执行视频任务时仍以 `SKILL.md` 及其直接引用资源为准。

## 新对话接手方式

1. 完整读取 `SKILL.md`，再按其中路由读取必需资源。
2. 读取本文件了解已确认的设计决策、失败方向和最近验证状态。
3. 把内置 V4 当作当前唯一稳定视觉基线，从现状继续迭代，不重新定义风格。
4. 新方案先在真实视频中验证；只有用户明确确认后，才写回 Skill 的稳定规则或资产。
5. 每次形成新的确认结论，同步更新 `SKILL.md`、对应 reference 与本文件。

新对话可直接说：`读取 f-remotion 的 SKILL.md 和 HANDOFF.md，从当前版本继续优化，不要重新设计。`

## Skill 目标

把目标视频和 SRT/时间轴制作成具有 V4 视觉基因的 Remotion 画中动效。核心能力不是套模板，而是理解台词关系，判断留白、复用、变通或新创，按关键词同步，保护原画面，并用克制的 Remotion 动效提升理解和情绪。

## 已确认的稳定基线

- 名称保持 `f-remotion`。
- 默认调用语保持简短：`使用 $f-remotion。`
- 无需再次提供参考视频；V4 样板已经内置。
- V4 的稳定基因是中文信息层级、透明根画布、局部细描边深色卡片、蓝绿红黄语义色、克制阴影、整词运动、柔和进退场与足够留白。历史单侧暗部渐变和全屏语义调色已废弃。
- V4 是视觉基因，不是封闭的六段结构或固定组件清单。
- 先理解语义，再选择留白、复用、变通或新创。允许编写新 Remotion 组件，但必须能说明它帮助观众看见了什么关系。
- 一个大视觉组对应一个完整叙事任务，不按字幕条数、句数或固定秒数切换；同一主锚点可以跨多句驻留。
- 一次只显示一个大视觉组；上一组完全退出后下一组才进入，组间可以有意留白。
- 元素跟随口播关键词逐步进入。新属性、证据、层级或转折出现时局部更新；继续解释同一信息时允许稳定保持。
- 中文承担主要信息。英文只保留原话、官方名称或必要行业缩写。
- 不使用扫描线、常驻进度条、技术网格、假数据、随机字符和无来源微文案。
- 动效保护人物、手势、原字幕、产品和用户已添加素材；人物占左侧时可将信息区移到右侧。
- SRT 默认只用于语义和帧时间轴，不自动生成成片字幕。
- 用户已插入截图、录屏、B-roll、画中画或信息卡的区间是硬禁区；包括场景根背景和退场残影在内的 Remotion 图层都不得进入。
- 国家、地区、平台、组织和产品可在确有识别价值时使用有来源的图标/标志；可靠数据可使用证据图表、数字增长和区间计数，不记忆固定 Logo、不虚构数据。
- 用户确认前不覆盖旧版，不修改 V4 基准资产，输出使用新文件名或独立 Composition。

## 已否决或明确不推荐的方向

- 每段固定放一个大英文标题。参考片中的行业缩写属于话题，不是风格模板。
- 为了“科技感”增加横扫线、扫描线、常驻进度条、技术网格或假数据。
- 为证明学会参考片而把其中所有组件强行塞进目标视频。
- 过多小标签、印章、图标和辅助文案。若主信息已经表达清楚，应删除这些小东西。
- 动效一开始快速全部播放完，随后长时间不变化。
- 相邻场景视觉交叠，或在上一组仍存在时让下一组出现。
- 只看参考片稳定帧，不分析入场顺序、阶段变化和退出方式。
- 将实验版本当作稳定基线；稳定基线只能由 `style-preset.md` 和内置 V4 资产定义。
- 让每个大动效携带不同色的全屏暗部渐变或调色层，再随场景一起淡入淡出。
- 按“每两句一个动效”、每条字幕或固定秒数机械切换大动效。

## 已沉淀的能力

- 语义匹配：重点、定义、顺序、因果、对比、并列、层级、边界、状态变化与数据。
- 必要性判断：人物表演或已有素材已经足够时主动留白。
- 原型能力：中文钩子、条件分支、决策路径、步骤状态链、核心揭晓、定义/实例、边界清单、结论确认卡。
- 可选构造能力：整词级联、状态替换、阶段轨道、视觉锚点驻留、实体标识行、确认动作、真实数字增长、区间计数、证据比较图、数据条、累积堆叠、门槛/解锁和概念组装。
- 创造流程：至少比较克制方案、表现方案与无动效基线，再选择最匹配当前台词和镜头的方案。
- 参考片学习：拆分为 V4 风格不变量、可迁移运动机制、不可照抄话题内容、素材/镜头依赖；未经用户确认的能力只保持实验或可选状态。

## 最近一次真实项目验证

最近使用一条约 12.6 秒、4K、59.94fps 的口播短片进行了完整验证。用户要求不显示字幕，并要求已经插入网页画面的区间不添加动效。

处理结果：

- SRT 仅用于语义同步，没有生成字幕层。
- 用户插入画面及其淡入淡出期间被标为硬禁区，完全没有 Remotion 图层。
- 其余口播只选择三个高价值语义点，分别采用数字重点、克制问题卡和分阶段核心揭示。
- 组间保留干净空隙，长组按新增台词逐步更新，避免提前播完后长期静止。
- 已通过 TypeScript/ESLint、关键帧、低清连续边界、4K 正式渲染和全片解码检查。

本次实战将“字幕默认不渲染”和“已有画面硬禁区”提升为稳定规则，已经写入 `SKILL.md`、`references/implementation.md` 与 `references/validation.md`。

## 2026-09-11 透明画布与叙事组迭代

用户复看上述成片后指出：三个大动效各自携带不同色的全屏渐变/调色层，且场景整体淡入淡出，导致原视频左侧背景随切组快速闪暗、闪亮和变色。根因已在 `DoubaoBusinessMotion.tsx` 的 `SceneCanvas` 中确认，不是单纯的退场帧数问题。

对 `参考视频1.mp4` 逐帧复核时，忽略了博主自己的截图、网页和视频画中画，只统计图形动效：

- 约 4.0–15.75 秒是同一个概念锚点。`FDE` 建立后跨多句驻留，未来周期、持续增长、不可替代和建议只做局部补充，没有按两句换景。
- 约 16.0 秒存在主动留白；17–19 秒附近的数据条只在“讨论热度/证据”语义成立时生长，基准、对照值和增幅按顺序完成。
- 约 20.5–25.25 秒把英文全称和中文拆解视为同一个定义任务，逐词/逐层组装后整体退出。
- 约 27.0–31.75 秒把国外、互联网大厂和二线城市/孵化园区放在同一个需求分层组中，国家与平台标志按层级逐行补入。
- 约 33.2–34.6 秒的数字表现先建立量级语境，再让区间上界增长到目标值，完成后稳定驻留；不是随机滚数。

本轮确认并写回：场景根画布默认透明；历史全屏暗部渐变/语义调色废弃；大动效按完整叙事任务而非句数分组；`enter/update/hold/exit/blank` 成为组内节奏事件；实体标识行、证据比较图和区间计数进入“可选”能力。局部深色卡片仍可保留，但不是动效背景。

## 新会话接手验证

2026-09-10 使用一个未继承旧聊天上下文的独立代理做了只读接手测试。代理仅凭 `SKILL.md`、本文件和原始视频/SRT，准确恢复了 V4 唯一稳定基线、实验版本非基线、已有画面硬禁区、SRT 默认不渲染、留白/语义策略、无交叠时间轴和全部禁用元素。未发现会阻塞下一会话的信息缺口。

2026-09-11 修改后又用未继承本轮诊断结论的独立代理做了 20.5 秒原始口播前向测试。它正确使用透明根画布，把跨句的“持续增长 + 难被替代”合并为同一 `visualGroupId`，对无可靠资产的平台实体降级为文字行，并按顺序处理 `643 → 5330 → +729%` 与 `30K–60K`。未出现按两句换景、虚构 Logo、虚构单位或全屏背景回退。

后续执行时仍需听取真实音频，微调 SRT 句内关键词的精确落点；SRT 只有句级时间时，不得把均匀字符分配当作最终词级同步。
